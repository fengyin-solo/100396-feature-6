# 地质灾害隐患点监测防治管理系统

面向地质灾害隐患点形变裂缝观测、雨量预警、避险搬迁安置与治理工程验收全流程的地质灾害防治数字化管理平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `geohazard-monitor-prevention:entries-v2` 这一项，或调用 `resetModule(模块)`。

## 雨量监测：站点代管权与审核流

雨量模块在通用流转之外加了一套代管权规则，改动点沿三条线定位：

- **站点编号 → 代管权表** `frontend/src/data/stations.ts`：站点编号 → 所属辖区（乡镇）→ 负责人。
  负责人为空表示站点交接中。
- **记录状态 → 审核流** `frontend/src/api/local-service.ts`：
  `已采集 →(乡镇站员提交) 待复核 →(区县复核) 已审核/达预警值`，复核驳回退回 `已采集`。
- **预警阈值 → 定级与通知**：复核通过时按 `threshold` 模块「已生效」的雨量阈值自动定级，
  达到后在 `alarm` 模块生成「待发布」通知。

规则明细：

- 乡镇站员只能登记、提交本辖区站点的记录；区县人员只读并负责复核；跨辖区操作一律拒绝
  （页面按身份隐藏动作，服务层同样拦截）。
- 记录的「归属乡镇」在登记时快照固化：站点之后移交，历史记录仍按原归属显示、按原归属校验权限。
- 雨量值同时达到多个级别时，**自动阈值定级（取最高级别），人工复核作为放行闸门**：
  复核不通过，任何级别都不生成通知。
- 审核通过且达预警值时，预警发布页生成「待发布」通知；同一雨量记录只生成一次。
- 同一审核结果重复提交只保留一次（按记录上的审核结果幂等拦截）。
- 交接期间站点无负责人：提交审核后转交区县待办（记录打「区县待办」标记），不会自动放行，
  由区县人员在待办中复核。

页面右上角可切换值班身份（乡镇站员/区县人员、所属乡镇），用于演示不同辖区下的权限差异。
